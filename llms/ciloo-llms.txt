# Ciloo

> Ciloo is a Rotterdam-headquartered global platform for branded products and promotional merchandise.
> Enterprises run a Ciloo brand store, and orders placed in it are produced on demand by a local
> production partner near the recipient — cutting cost, waste and shipping distance while keeping brand
> control central. Ciloo exposes two documented APIs: a per-brand-store Cart API (OAuth 1.0a) for
> placing items in a customer's cart and handing them a signed auto-login link, and a Printer API
> integration (bidirectional webhooks) for routing orders to production partners and receiving
> production and shipping status back.

## APIs

- [Ciloo Cart API](https://api.cilooprint.com/ciloo-cart-api-documentation/): OAuth 1.0a (HMAC-SHA1)
  REST API on the `ciloo/v1` namespace of a brand store — get/add/update/remove cart items, mint
  per-customer OAuth credentials, and issue one-hour auto-login tokens. Customer records are created
  and updated through the WooCommerce `wc/v3` namespace on the same host. Documentation version 2.0.0,
  last updated 2025-08-18.
- [Ciloo Printer API Integration](https://api.cilooprint.com/printer-api-integration/): order submission
  from Ciloo to a production partner's own endpoint, and production-status plus shipping callbacks from
  the partner back to a Ciloo-owned inbound URL.

## Base URL

There is no single shared API host. Every brand store is its own hostname — a Ciloo-hosted
`<tenant>.cilooprint.com` subdomain or a customer-owned domain — and the API is served from `/wp-json`
on that host. The documentation writes the base as `https://your-domain.com/wp-json/ciloo/v1/`.

## What Ciloo does not publish

- No OpenAPI or AsyncAPI document of its own.
- No SDK on any public package registry, and no GitHub organization; the PHP, JavaScript and Python
  reference implementations are printed inline in the documentation.
- No pricing page, no public developer sign-up — access comes with a brand-store contract.
- No published rate limits and no rate-limit response headers.
- No idempotency contract on any write operation.
- No status page, SLA or deprecation policy.
- No /.well-known/ documents, no security.txt, no MCP server and no A2A agent card.
